# Haidar System — Project Proof

## Purpose

Projects are evidence of capability. They should strengthen the brand without becoming the brand itself.

## Project Story Format

Every public project should answer:

1. **Problem** — What needed solving?
2. **Demand / Reason** — Why was it worth solving?
3. **System** — What was built?
4. **Implementation** — How does it work?
5. **Result** — What changed or was learned?
6. **Next Step** — What remains uncertain?

## Maturity Labels

Use honest status labels:

- Idea
- Research
- Experiment
- Prototype
- MVP
- Validated
- Active
- Delivered
- Archived

## Project Selection

A project is strong brand evidence when it demonstrates at least one of:

- Real demand
- Strong systems thinking
- Useful execution
- Technical integration
- Meaningful learning
- Measurable improvement

## Presentation Rule

Never imply that a prototype is a production system, an experiment is a validated business, or a capability is a proven service without evidence.

## Brand Relationship

```text
Haidar System
    ↓
Capabilities + Thinking
    ↓
Experiments / Projects
    ↓
Evidence
    ↓
Validated opportunities
```
